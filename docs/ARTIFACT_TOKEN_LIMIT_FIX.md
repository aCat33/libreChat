# Artifact代码生成中断问题修复

## 问题描述

**用户反馈:** artifacts生成代码生到一半就不动了

**截图显示:** 代码在第78行 `{ date: '` 突然中断

---

## 根本原因

### 1. Token限制 ⭐⭐⭐ (主要原因)

**配置文件中的限制:**
```yaml
# 千问端点
addParams:
  max_tokens: 2000  # ⚠️ 太小!
  
# DeepSeek端点  
addParams:
  max_tokens: 4096  # ⚠️ 对大量数据也不够
```

**问题分析:**
- 用户生成的是包含大量数据的数组
- 每行数据约80 tokens
- 50-70行数据 = 4000-5600 tokens
- **超过限制后,AI强制中断生成**

**截图中的代码:**
```typescript
const rawData = [
  { date: '2020-08-09', depth: 3993.0, daily_footage: 5.0, ... },
  { date: '2020-08-10', depth: 4014.0, daily_footage: 21.0, ... },
  // ... 继续生成到第78行
  { date: '  // ← 在这里超过2000 tokens限制,中断!
```

### 2. 完整性检查的副作用 ⭐⭐

当代码因token限制中断后:
- 代码结构不完整(引号未闭合、数组未完成)
- 我们的完整性检查检测到不完整
- 显示"正在生成代码..."
- **但实际上AI已经停止生成!**
- 用户看到一直在加载,实际上代码永远不会完整

---

## 修复方案

### 修复1: 增加max_tokens限制 (立即生效)

**修改文件:** `librechat33.yaml`

```yaml
# 千问端点 - 从2000增加到8000
- name: "Qwen"
  addParams:
    max_tokens: 8000  # ✅ 增加4倍
    temperature: 0.7

# DeepSeek端点 - 从4096增加到8000  
- name: "DeepSeek"
  addParams:
    max_tokens: 8000  # ✅ 增加约2倍
    temperature: 1
```

**效果:**
- 支持生成更长的代码
- 可以包含更多数据行
- 大多数artifact都能完整生成

**需要:**
```bash
# 重启后端服务以应用配置
npm run backend:dev
```

---

### 修复2: 完整性检查的超时强制渲染

**修改文件:** `client/src/components/Artifacts/ArtifactPreview.tsx`

**新增逻辑:**
```typescript
// 检查代码完整性
const isComplete = hasValidStructure();
setIsCodeComplete(isComplete);

// ⭐ 关键:如果代码不完整但AI已停止生成(isSubmitting=false)
// 等待2秒后强制允许渲染,以便用户看到错误或手动修复
if (!isComplete && !isSubmitting) {
  setTimeout(() => {
    setIsCodeComplete(true);  // 强制允许渲染
  }, 2000);
}
```

**效果:**
- 如果代码不完整但AI已停止
- 等待2秒后自动尝试渲染
- 用户可以看到错误,然后:
  - 点击"重试渲染"
  - 或切换到Code标签手动补全代码
  - 或重新发送消息增加提示"请简化数据"

## Token限制参考

### 不同场景的Token消耗:

| 代码类型 | 代码长度 | 预估Token | 建议max_tokens |
|---------|---------|-----------|----------------|
| 简单组件 | 50行 | 500-800 | 2000 ✅ |
| 中等组件 | 150行 | 1500-2500 | 4000 ✅ |
| 复杂组件 | 300行 | 3000-5000 | 8000 ✅ |
| 大量数据 | 500行+ | 5000-8000+ | 8000-16000 |

### 你的场景:
```
代码类型: 包含大量钻井数据的数组
预估行数: 100-200行
Token消耗: ~6000-10000
原配置: 2000 (千问) / 4096 (DeepSeek) ❌
新配置: 8000 ✅
```

## 副作用和注意事项

### 增加max_tokens的影响:

✅ **正面影响:**
- 支持更长的代码生成
- 更少的代码中断
- 更好的用户体验

## 总结

### 问题:
❌ Artifacts代码生成中断在中途

### 原因:
⚠️ max_tokens限制过小 (2000/4096)
⚠️ 大量数据代码超过限制
⚠️ 完整性检查无法区分"生成中"和"已中断"

### 修复:
✅ max_tokens: 2000 → 8000 (千问)
✅ max_tokens: 4096 → 8000 (DeepSeek)
✅ 添加超时强制渲染机制

### 效果:
🎯 支持生成4倍长的代码
🎯 大多数artifact可完整生成
🎯 即使超限也不会永远卡住
