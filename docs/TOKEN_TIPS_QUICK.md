# ⚡ Token超限快速解决方案

## 🎯 三个核心技巧

### 技巧1️⃣: 数量与逻辑分离

**❌ 错误:**
```
"帮我画折线图,包含这5000行数据: [大量数据]"
→ 必然截断
```

**✅ 正确:**
```
"帮我写ECharts看板框架,用20个Mock数据测试即可"
→ 完整生成,后续接入真实数据
```

---

### 技巧2️⃣: 代码截断后"继续"

**发现截断时:**
```
"代码截断了,请从最后两行代码后继续输出剩余代码"
```

**然后:**
1. 复制第一段代码
2. 复制继续生成的代码  
3. 在Code标签手动合并

---

### 技巧3️⃣: 简体化生成

**分步生成:**

```
第1步: "生成HTML骨架和CSS样式(不需要JS)"
第2步: "现在写ECharts配置项代码"
第3步: "合并成完整可运行代码"
```

```

第2步提示:  
"实现左上角折线图,用generateMockData(15)生成数据"

第3步提示:
"实现右上角柱状图..."
```

### 模板3: Mock数据策略

```typescript
// ✅ 好做法:数据生成函数
const generateMockData = (count = 20) => {
  return Array.from({ length: count }, (_, i) => ({
    date: `2020-08-${i + 1}`,
    depth: 4000 + i * 10,
    drill_speed: 60 + Math.random() * 40,
  }));
};

// ❌ 坏做法:硬编码100行数据
const data = [
  { date: '...', depth: 4000, ... },
  { date: '...', depth: 4010, ... },
  // ... 100行 ← Token爆炸!
];
```

## 🚀 快速检查清单

**生成Artifact前问自己:**

- [ ] 是否包含超过30行的硬编码数据? → 改用Mock函数
- [ ] 代码是否超过300行? → 考虑分步生成
- [ ] 是否可以先生成框架? → 先框架后细节
- [ ] 数据能否后续API接入? → 预留接口

**如果全选"是",你的代码很可能被截断!**

## 💡 Token消耗速查表

| 内容 | Token估算 | 是否安全 |
|------|-----------|----------|
| 20行Mock数据 | ~200 | ✅ |
| 100行Mock数据 | ~1000 | ⚠️ |
| 500行硬编码数据 | ~5000+ | 🔴 必截断 |
| 简单组件(50行) | ~500 | ✅ |
| 复杂组件(300行) | ~3000 | ✅ |
| 超大应用(800行+) | ~8000+ | 🔴 需分步 |

## 📞 快速问题解决

### Q1: 还是被截断怎么办?

**立即尝试:**
1. 发送"继续生成剩余代码"
2. 检查提示词是否有大量数据
3. 改用分步生成策略

### Q2: 分步生成的代码如何合并?

**方法:**
1. 每步生成后复制代码
2. 在Code标签粘贴整合
3. 或最后一步提示"合并上述代码"

### Q3: Mock数据不够真实?

**改进:**
```typescript
const generateRealisticData = (count = 20) => {
  return Array.from({ length: count }, (_, i) => ({
    date: new Date(2020, 7, i + 1).toISOString().split('T')[0],
    depth: 4000 + i * 10 + Math.random() * 5,
    drill_speed: 60 + Math.sin(i / 3) * 20,
    // 添加真实波动
  }));
};
```

## 🎯 记住这些

1. **数据≠代码** - 永远分离
2. **分步>一次性** - 降低风险
3. **Mock优先** - 开发期用Mock,生产用API
4. **预留接口** - 一开始就设计好数据来源
5. **善用继续** - 截断不慌,让AI接着写
