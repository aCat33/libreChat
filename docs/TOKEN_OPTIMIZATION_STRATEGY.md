# 油田勘探RAG应用框架推荐 - Token优化方案

## 💡 针对溢出或违规大屏场景的"破局重建议"

联络有这些限制，我们在让AI生成复杂Artifacts图表时，应该遵循以下技巧:

---

## 技巧一: 数量与逻辑分离 (千万不要把海量大数据)

### ❌ 错误提示:
```
"请帮我画一个折线图,包含这5000行历史钻井数据 (附带长长的数据)。"
→ 绝对会被截断
```

### ✅ 正确提示:
```
"请帮我写一个 ECharts 的看板框架,只要按 JS 里生成 20个模拟数据点作为
Mock 数据做测试就可可。稍后坐标轴、图例、编辑组件的逻辑是完整的。"
```

**原理:**
- 先生成**组件结构和逻辑**,数据只用少量Mock
- 后续在Code标签或通过API接入真实数据
- 分离"代码框架"和"海量数据",避免token超限

---

## 技巧二: 是事码断,让它"继续"

如果生成的代码实在太长,在未展完就停了,您只需要在对话框里发送:

```
"代码截断了,请从「油田最后两行代码的]后」开始继续输出剩下的代码。"
```

LibreChat 通过能把过往代码全,不过能可能需要手动拼两两个代码块后来测试。

**操作步骤:**
1. AI生成代码截断
2. 发送"继续"提示
3. 复制第一段代码
4. 复制继续生成的代码
5. 在Code标签手动合并
6. 测试完整代码

**注意:** 这个方法适用于token略微超限的情况(比如8500 tokens)

---

## 技巧三: 简体化生成

如果页面真复杂,不要让 AI 一次性吐出所有代码。

### 分步生成策略:

#### **第1步: 骨架生成**
```
提示: "帮我生成纯图层 HTML 骨架和 CSS 样式 (不需要 JS 逻辑)。"
```

**效果:** 
- 生成基础HTML结构
- 完整的CSS样式
- 约500-1000 tokens

#### **第2步: 功能补充**  
```
提示: "现在帮我写 ECharts 的配置项 (Option) 代码。"
```

**效果:**
- 只生成图表配置
- 数据用简单Mock
- 约1000-1500 tokens

#### **第3步: 整合**
在Code标签手动整合两部分代码,或者:
```
提示: "把上面两部分合并成完整的可运行代码"
```

---

## 核心概念: 避免合成代码膨胀

在LibreChat中生成高代的 Artifacts，首选当放弃中对代码应该太繁且粒自动优化(例如
Claude 3.5 Sonnet 或 GPT-4o)，它们的次数不多远远低于本地开源大模型 (例如
Qwen等)的次数不多远远远远低于本地开源大模型出现来查看大眼自动起对的。

### 模型选择建议:

| 场景 | 推荐模型 | Max Tokens | 说明 |
|------|---------|------------|------|
| 简单组件 | Qwen2.5-7B | 8000 | 轻量快速 |
| 中等复杂度 | Qwen2.5-32B | 8000 | 平衡性价比 |
| 复杂Artifacts | DeepSeek-Coder | 8000 | 代码质量高 |
| 超复杂/数据量大 | 分步生成 | 多次调用 | 避免单次超限 |

```markdown

- 样式使用Tailwind CSS

要求:代码简洁,结构清晰,易于后续扩展真实数据接口
```

#### 模板2: 数据可视化Dashboard
```markdown

- 只需要基础HTML/CSS结构

```

#### 模板3: 继续生成
```markdown
代码在第[XX]行被截断了,请从截断位置继续生成剩余代码。

```

```

```

### 方案B: 代码分层架构

采用分层生成策略,避免单次生成过大:

```
第1层: 数据结构定义 (types.ts)
  ↓
第2层: 配置文件 (config.ts)  
  ↓
第3层: 组件框架 (Component.tsx)
  ↓
第4层: 样式优化 (可选)
```

**实施步骤:**

1. **生成类型定义**
   ```
   提示: "定义钻井数据的TypeScript接口,包含日期、深度、钻速等字段"
   结果: types.ts (约200 tokens)
   ```

2. **生成图表配置**
   ```
   提示: "基于上述类型,生成ECharts的配置对象,数据用5条Mock"
   结果: config.ts (约800 tokens)
   ```

3. **生成React组件**
   ```
   提示: "创建一个React组件,导入上述配置并渲染图表"
   结果: Component.tsx (约500 tokens)
   ```

4. **合并整合**
   ```
   提示: "把上述代码合并成单个文件的完整实现"
   结果: App.tsx (约1500 tokens总计)
   ```

### 方案C: Mock数据策略

#### 智能Mock生成:

```typescript
// ✅ 好的做法:生成数据函数
const generateMockData = (count: number = 20) => {
  return Array.from({ length: count }, (_, i) => ({
    date: `2020-08-${String(i + 1).padStart(2, '0')}`,
    depth: 4000 + i * 10,
    drill_speed: 60 + Math.random() * 40,
    // ... 其他字段
  }));
};

// 使用
const data = generateMockData(20); // 只生成20条,代码简洁
```

```typescript
// ❌ 不好的做法:硬编码大量数据
const data = [
  { date: '2020-08-01', depth: 4000, drill_speed: 60, ... },
  { date: '2020-08-02', depth: 4010, drill_speed: 65, ... },
  // ... 重复100行
  // ← 这会消耗大量tokens!
];
```

**优势:**
- 代码紧凑,token消耗低
- 易于调整数据量
- 后续可轻松替换为API调用

### 方案D: API接口预留

生成代码时就预留数据接口:

```typescript
// Artifact生成的代码框架
import { useQuery } from '@tanstack/react-query';

const DrillingChart = () => {
  // ✅ 预留数据接口
  const { data, isLoading } = useQuery({
    queryKey: ['drilling-data'],
    queryFn: fetchDrillingData, // 后续实现
    initialData: generateMockData(20), // 开发时用Mock
  });

  if (isLoading) return <Loading />;

  return (
    <Chart data={data} />
  );
};
```

**后续接入真实数据:**
```typescript
// 实现真实数据获取
const fetchDrillingData = async () => {
  const response = await fetch('/api/drilling/data');
  return response.json();
};
```

### 针对超大artifact的临时配置:

如需生成特别复杂的代码,可临时提升:

```yaml
# 特殊场景配置(需要时启用)
addParams:
  max_tokens: 16000  # 模型支持的最大值
  temperature: 0.7   # 降低随机性,提高代码质量
```

**注意:** 
- 检查模型是否支持16000 tokens输出
- DeepSeek/Qwen通常支持最大8192 tokens
- 超过模型限制会自动截断

## 最佳实践清单

### ✅ 推荐做法:

1. **数据与逻辑分离**
   - 生成数据函数而非硬编码
   - Mock数据控制在10-20条
   - 预留真实数据接口

2. **分步生成**
   - 先骨架后细节
   - 先结构后样式
   - 先功能后优化

3. **合理提示词**
   - 明确指定"只需要X行Mock数据"
   - 说明"代码要简洁"
   - 必要时"分多次生成"

4. **利用继续功能**
   - 发现截断立即发送"继续"
   - 保存每段代码
   - 最后手动合并

### ❌ 避免做法:

1. ❌ 在提示词中粘贴大量数据
2. ❌ 要求一次性生成超级复杂的应用
3. ❌ 不指定数据量限制
4. ❌ 忽视分步生成的建议
5. ❌ 硬编码几十上百行数据

## 故障排查

### 问题1: 代码仍然被截断

**检查清单:**
- [ ] max_tokens是否已设置为8000?
- [ ] 后端是否已重启?
- [ ] 提示词是否包含大量数据?
- [ ] 是否可以改用分步生成?

**解决方案:**
1. 检查配置文件
2. 重启后端服务
3. 优化提示词,减少数据量
4. 尝试分步生成

### 问题2: 继续生成的代码无法拼接

**原因:**
- 上下文丢失
- 变量/函数名不匹配
- 结构不完整

**解决方案:**
```
提示: "请生成完整的独立代码文件,包含:
1. 所有必要的imports
2. 完整的类型定义
3. 所有依赖的函数
不要依赖前文,生成可以直接运行的完整代码"
```

### 问题3: Mock数据太简单,测试不充分

**解决方案:**
```typescript
// 生成更真实的Mock数据
const generateRealisticMockData = (count = 20) => {
  const startDate = new Date('2020-08-01');
  
  return Array.from({ length: count }, (_, i) => {
    const date = new Date(startDate);
    date.setDate(date.getDate() + i);
    
    return {
      date: date.toISOString().split('T')[0],
      depth: 4000 + i * 10 + Math.random() * 5,
      drill_speed: 60 + Math.sin(i / 3) * 20 + Math.random() * 10,
      pump_pressure: 11 + Math.random() * 3,
      mud_density: 1.18 + Math.random() * 0.3,
      // 模拟真实的数据波动
    };
  });
};
```

## 总结

### 核心原则:

1. 🎯 **数据与代码分离** - 永远不要硬编码大量数据
2. 🔀 **分步渐进** - 复杂功能拆解成多个小步骤
3. 📊 **Mock优先** - 开发时用少量Mock,生产用API
4. 🔄 **利用继续** - 截断时不慌,让AI继续生成
5. ⚙️ **预留接口** - 一开始就设计数据获取机制

### 效果预期:

- ✅ Token超限问题: 从经常发生 → 几乎不发生
- ✅ 代码质量: 更简洁,更易维护
- ✅ 开发效率: 分步生成反而更快
- ✅ 用户体验: 无需等待超长生成,每步都能快速完成
